# Crypto Arbitrage Bot

Асинхронный торговый бот на Python, который параллельно запускает пять
независимых арбитражных стратегий поверх пяти централизованных бирж (CEX) и
нескольких DEX. Все стратегии работают в своих `asyncio`-корутинах, а единый
риск-менеджер контролирует весь капитал и может полностью остановить торговлю
при превышении лимитов.

> ⚠️ **Дисклеймер.** Проект носит образовательный и демонстрационный характер.
> Это не финансовая рекомендация. Торговля криптовалютой сопряжена с риском
> полной потери средств. По умолчанию бот запускается в режиме `DRY_RUN`
> (симуляция без реальных сделок). Используйте на свой страх и риск.

## Возможности

- **5 стратегий**, работающих одновременно и независимо:
  - `CEXScanner` — CEX–CEX арбитраж: спреды между Bybit, KuCoin, OKX, Gate.io, Bitget.
  - `DEXScanner` — DEX–CEX арбитраж с хеджированием шортом на фьючерсе.
  - `BasisScanner` — basis trading на расхождении спота и перпетуального фьючерса.
  - `FutureScanner` — cash-and-carry фьючерсный арбитраж (спот + шорт срочного фьючерса).
  - `BotFunding` — фандинг-арбитраж: дельта-нейтральная позиция ради ставки финансирования.
- **Единый риск-менеджмент** — проверка каждой сделки перед исполнением,
  дневные лимиты убытка, счётчик открытых позиций, глобальный стоп.
- **Разделение сканирования и исполнения** через очередь сигналов
  (`SignalQueue`) — стратегии только находят возможности, `Executor` их исполняет.
- **Управление через Telegram** — команды `/status`, `/stop`, `/start`,
  `/resume`, `/report`; принимаются только с доверенного `chat_id`.
- **Устойчивость к сбоям сети и кривым ответам API** — обработка ошибок на
  уровне бирж и стратегий, чтобы одна упавшая корутина не роняла бота.
- **Конфигурация в одном файле** (`config.py`), секреты — только в `.env`.

## Архитектура

```
main.py                 — точка входа: инициализация и запуск всех корутин
config.py               — все настройки (капитал, лимиты, интервалы, монеты)
logger.py               — единый логгер

core/
  balance_manager.py    — балансы на всех биржах, проверка достаточности средств
  risk_manager.py       — глобальный риск-контроль, лимиты, стоп бота
  signal_queue.py       — очередь сигналов между стратегиями и исполнителем
  executor.py           — исполнение ордеров с проверкой риска и баланса

exchanges/              — обёртки над CEX (bybit, kucoin, okx, gate, bitget)
  exchange_manager.py   — центральный менеджер подключений (на базе ccxt)

dex/                    — обёртки над DEX (uniswap, pancakeswap, quickswap, camelot)
  dex_manager.py        — менеджер DEX-подключений (на базе web3)

strategies/             — пять арбитражных стратегий-сканеров

notifications/
  telegram.py           — управление и уведомления через Telegram
```

Поток данных: **стратегии → SignalQueue → Executor → биржа**, при этом
`RiskManager` и `BalanceManager` дают разрешение (или отказ) на каждую сделку.

## Стек

- Python 3.12, `asyncio`
- [`ccxt`](https://github.com/ccxt/ccxt) — унифицированный API для CEX
- [`web3`](https://web3py.readthedocs.io/) — работа с DEX on-chain
- `python-dotenv` — загрузка ключей из `.env`

## Установка и запуск

```bash
# 1. Клонировать и перейти в папку
git clone <repo-url>
cd crypto-arbitrage-bot

# 2. Виртуальное окружение
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate

# 3. Зависимости
pip install -r requirements.txt

# 4. Ключи: скопировать шаблон и заполнить своими значениями
cp .env.example .env
#   отредактировать .env — вписать ключи бирж и Telegram

# 5. Запуск (по умолчанию DRY_RUN=True — без реальных сделок)
python main.py
```

Остановка — `Ctrl+C` или команда `/stop` в Telegram.

## Конфигурация

Все параметры — в `config.py`:

- `DRY_RUN` — режим симуляции (по умолчанию `True`). Переключать на реальную
  торговлю осознанно.
- `TOTAL_CAPITAL_USD`, `CAPITAL_ALLOCATION` — общий капитал и его распределение
  по стратегиям.
- `RISK` — лимиты риска (макс. дневной убыток, размеры позиций и т.д.).
- `THRESHOLDS`, `INTERVALS`, `COINS` — пороги входа, частоты сканирования,
  списки монет.

Секреты (`API_KEY`, `API_SECRET`, `WALLET_PRIVATE_KEY`, токен Telegram)
хранятся **только в `.env`** и никогда не попадают в код или в репозиторий —
см. `.env.example` для списка нужных переменных.

## Безопасность

- `.env` добавлен в `.gitignore` и **не** коммитится.
- Ключи читаются исключительно через `os.getenv(...)`.
